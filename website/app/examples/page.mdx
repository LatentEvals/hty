# Examples

Real-world scenarios you can copy and adapt. Each one shows something that agents couldn't do before `hty`.

## Scaffold a Next.js project

`create-next-app` asks 5+ interactive questions. Agents used to be locked out of this entirely, or had to guess at `--flag` equivalents that break when the tool adds a new prompt.

```sh
hty run --name scaffold -- npx create-next-app@latest my-app

# answer each prompt as it appears
hty wait scaffold --text "TypeScript" --timeout 10000
hty send scaffold --text "y\n"

hty wait scaffold --text "ESLint" --timeout 5000
hty send scaffold --text "y\n"

hty wait scaffold --text "Tailwind" --timeout 5000
hty send scaffold --text "y\n"

hty wait scaffold --text "src/" --timeout 5000
hty send scaffold --text "y\n"

hty wait scaffold --text "App Router" --timeout 5000
hty send scaffold --text "y\n"

hty wait scaffold --text "import alias" --timeout 5000
hty send scaffold --text "\n"

# wait for install to finish
hty wait scaffold --exit --timeout 120000
```

The agent reads the actual question on screen and answers it. If `create-next-app` adds a new prompt next month, the agent handles it — no code change needed.

## Stage specific git hunks

`git add -p` walks through each diff hunk and asks `Stage this hunk [y,n,q,a,d,/,e,?]?`. Agents can now review each hunk and make targeted decisions.

```sh
hty run --name review -- git add -p

# review the first hunk
hty wait review --text "Stage this hunk" --timeout 5000
hty snapshot review   # agent reads the diff and decides
hty send review --text "y\n"

# skip the second hunk
hty wait review --text "Stage this hunk" --timeout 5000
hty snapshot review   # this one is just whitespace
hty send review --text "n\n"

# quit
hty send review --text "q\n"
hty wait review --exit --timeout 3000
```

## Authenticate with GitHub CLI

`gh auth login` is a multi-step interactive flow. The agent navigates each menu.

```sh
hty run --name ghauth -- gh auth login

# choose GitHub.com
hty wait ghauth --text "GitHub.com" --timeout 5000
hty send ghauth --key enter

# choose HTTPS
hty wait ghauth --text "HTTPS" --timeout 5000
hty send ghauth --key enter

# authenticate with browser
hty wait ghauth --text "Login with a web browser" --timeout 5000
hty send ghauth --key enter

# wait for the one-time code to appear
hty wait ghauth --text "one-time code" --timeout 10000
hty snapshot ghauth   # agent reads the code and tells the user
```

## Run SQL queries in psql

Drive a Postgres REPL session — execute queries, read tabular output from the rendered screen.

```sh
hty run --name db -- psql -U postgres mydb

# wait for the prompt
hty wait db --text "mydb=#" --timeout 5000

# run a query
hty send db --text "SELECT count(*) FROM users WHERE created_at > now() - interval '7 days';\n"
hty wait db --idle 500 --timeout 5000
hty snapshot db   # agent reads the result table

# run another
hty send db --text "SELECT email FROM users ORDER BY created_at DESC LIMIT 5;\n"
hty wait db --idle 500 --timeout 5000
hty snapshot db

# exit
hty send db --text "\\q\n"
hty wait db --exit --timeout 3000
```

## Monitor a TUI dashboard

Have an agent observe `btop`, `htop`, or `k9s` and react to what's on screen.

```sh
hty run --name monitor -- btop

# let it render
hty wait monitor --idle 1000 --timeout 10000

# read the dashboard
hty snapshot monitor

# agent can check this periodically
# and alert when CPU > 90% or memory is low
```

The `snapshot` returns the fully rendered terminal — not raw ANSI escape sequences — so the agent sees a readable screen, just like a human would.

## Edit a file in vim

For cases where diff-based editing is awkward (binary files, complex multi-cursor edits, or when you need to see context), drive vim directly.

```sh
hty run --name edit -- vim config.yaml

# navigate to the line we want to change
hty send edit --text "/database_url\n"
hty wait edit --idle 200 --timeout 3000

# change the value
hty send edit --text "ciw"               # delete the word under cursor
hty send edit --text "new-db.example.com"
hty send edit --key esc

# save and quit
hty send edit --text ":wq\n"
hty wait edit --exit --timeout 3000
```

## CI smoke test for a CLI tool

Validate that your interactive CLI actually works end-to-end. This runs in CI — no human needed.

```sh
#!/bin/bash
set -e

# test that our CLI's setup wizard works
hty run --name test-setup -- ./my-cli init

hty wait test-setup --text "Project name:" --timeout 5000
hty send test-setup --text "test-project\n"

hty wait test-setup --text "Choose a template:" --timeout 5000
hty send test-setup --key down        # select second option
hty send test-setup --key enter

hty wait test-setup --text "Created test-project" --timeout 10000
hty wait test-setup --exit --timeout 5000

# verify the output
[ -d "test-project" ] || exit 1
echo "setup wizard works"
```

## Pair with a live session

One person (or agent) runs the session, another watches live — or even co-drives it.

```sh
# terminal A: start the session
hty run --name pair -- vim project.py

# terminal B: watch what's happening (read-only)
hty watch pair

# terminal C: attach and co-edit (bidirectional)
hty attach pair
# Ctrl-A d to detach
```

Multiple clients can `attach` to the same session simultaneously. `watch` is always read-only.
