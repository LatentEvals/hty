# Commands

```
hty <command> [args...]
```

Sessions are identified by a `--name` you choose or by their UUIDv7 (shown as its first 8 chars). Any unambiguous prefix works. If only one session is running, the session argument can be omitted entirely.

---

## run

Start a program in a new detached PTY session. The session runs in the background — use `watch`, `snapshot`, or `attach` to interact with it.

```sh
hty run --name my-session -- vim /tmp/foo.txt
hty run --name db -- psql -U postgres
hty run -- btop                          # auto-generated name
```

The server auto-starts on first use. No setup required.

## snapshot

Read the current rendered screen. Returns the terminal as readable text — not raw ANSI escapes — so agents and scripts can parse it directly.

```sh
hty snapshot my-session
```

This is the primary way agents "see" what's happening. The output is the same screen a human would see in the terminal.

## send

Send keystrokes to a session. Supports text, named keys, and C-style escape sequences.

```sh
hty send my-session --text "hello world"
hty send my-session --text "y\n"           # text with newline
hty send my-session --key esc
hty send my-session --key enter
hty send my-session --key up
hty send my-session --key ctrl-c
```

Run `hty keys` for the full list of supported key names.

## wait

Block until a condition is met. This is what makes `hty` reliable — no more `sleep 2` and hope.

```sh
# wait for specific text to appear on screen
hty wait my-session --text "Stage this hunk" --timeout 5000

# wait for output to settle (no new output for N ms)
hty wait my-session --idle 300 --timeout 5000

# wait for the process to exit
hty wait my-session --exit --timeout 30000
```

| Flag | What it does |
| --- | --- |
| `--text PATTERN` | Block until the substring appears on the rendered screen |
| `--idle MS` | Block until no output for the given duration |
| `--exit` | Block until the session's process exits |
| `--timeout MS` | Give up after this many milliseconds (exit code 3) |

Always use `--timeout`. An agent stuck in an infinite `wait` is worse than one that fails fast.

## watch

Observe a session's rendered screen in real time. Read-only — you see what's happening without affecting it.

```sh
hty watch my-session
```

Great for debugging what an agent is doing, or demoing an automated workflow. Press `Ctrl-C` to stop watching.

## attach

Interactively attach to a running session. Bidirectional — you can type, and so can the agent. Multiple clients can attach concurrently.

```sh
hty attach my-session
```

Detach with `Ctrl-A d`. The session continues running after you detach.

## list

Show all sessions — running, exited, and killed.

```sh
hty list
```

## logs

Show the event log for a session. Works for running and exited sessions, and persists across server restarts.

```sh
hty logs my-session
hty logs my-session --follow           # tail -f style
hty logs my-session --since 30s --json # structured output
```

Events include: spawn, input, output, title changes, bell, exited, failed, killed.

## replay

Replay a recorded session through a fresh VT engine in memory. No side effects — nothing is re-executed.

```sh
hty replay my-session
hty replay my-session --speed 3          # 3x playback speed
hty replay my-session --at 5s --to 10s   # jump to a time range
hty replay my-session --loop             # loop continuously
```

Holds on the final frame until `Ctrl-C`. Useful for debugging, demos, or post-mortem analysis.

## kill

Terminate a session's process. The recording is preserved — `logs` and `replay` still work.

```sh
hty kill my-session
```

## delete

Permanently remove a session record and its log file. Frees the session name for reuse.

```sh
hty delete my-session
```

## keys

Print all supported symbolic key names for `hty send --key`.

```sh
hty keys
```

## info

Show resolved paths and server status. Useful for finding the socket path when setting up [SSH tunnels](/remote) for remote observation.

```sh
$ hty info
socket:  /Users/me/.local/state/hty/sock
logs:    /Users/me/.local/state/hty/logs
server:  running
```

Environment variables that affect paths (`$HTY_SOCKET`, `$XDG_RUNTIME_DIR`, `$XDG_STATE_HOME`) are shown if set.
